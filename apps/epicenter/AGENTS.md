# Epicenter

One desktop application host. Bun serves the trusted SPAs, APIs, WebSockets,
and Home session; Rust owns native application mechanisms.

Design authority: [ADR-0190](../../docs/adr/0190-a-build-declares-which-epicenter-owns-its-data-not-which-window-it-runs-in.md) (a compiled application is a declared `dist/<id>` build; its "`epicenter-host` says the host owns its replica" half is withdrawn by ADR-0226, which a build no longer declares at all), [ADR-0209](../../docs/adr/0209-epicenter-is-the-raw-view-beside-its-applications-not-a-shell-above-them.md) (Epicenter is an application beside the others: it shows the data raw, the applications are the crafted views, and the OS is the launcher and switcher), [ADR-0189](../../docs/adr/0189-home-launches-applications-into-their-own-windows-and-stays-open-behind-them.md) (one launchable list, one Home-owned launch verb, per-application windows; its Home-as-shell framing is withdrawn by ADR-0209), [ADR-0179](../../docs/adr/0179-an-installed-app-is-an-inert-built-folder-admitted-through-one-static-artifact-boundary.md) (one static-artifact admission boundary for one immutable app catalog; supersedes ADR-0153), [ADR-0180](../../docs/adr/0180-epicenter-has-one-host-owned-active-local-transcription-model.md) (one host-owned active local transcription model), [ADR-0152](../../docs/adr/0152-epicenter-home-is-a-shell-above-workspaces.md) (what Home owns; read its title as history, since ADR-0209 withdrew "above"), [ADR-0151](../../docs/adr/0151-local-workspace-stores-use-owner-first-directories.md) (owner-scoped local stores), [ADR-0118](../../docs/adr/0118-epicenter-is-one-trusted-bun-hosted-spa-origin.md) (one trusted application origin), [ADR-0080](../../docs/adr/0080-the-super-app-is-a-desktop-host-cross-device-is-remote-access-to-the-session-not-a-per-app-capability-plane.md) (remote devices attach to the session, never to per-app endpoints), and [ADR-0113](../../docs/adr/0113-super-chat-session-commands-are-host-owned-transports-only-frame-them.md) (Home owns command semantics; transports only frame and deliver them).

## Shape

- `src/applications.ts` declares the compiled applications and composes what Home lists as launchable: compiled applications plus the selected catalog generation's members, in one `{ id, title }` shape served at `/api/apps`. That list is not "the catalog": `catalog` keeps its ADR-0179 meaning, the immutable generation of admitted folders. Do not surface "compiled versus admitted" to a user.
- Epicenter is an application beside the others, not a shell above them (ADR-0209). Applications keep their own windows and the OS is the launcher and switcher, so do not build an in-app application switcher, a command palette over rows, or anything that indexes rows into an OS search index. Closing Epicenter must leave every other window running. Epicenter's own job is the raw view: a sidebar of namespaces over `openInspection`, where picking one is `selectLens` and "Everything raw" is `clearLens`. Grouping by namespace is the mode, not a view option, because a table name is unqualified only inside one interpretation; there is deliberately no friendly view spanning two namespaces. The pane does not build today: `src/inspect.ts` imports `openInspection` from the deleted `@epicenter/data/legacy/inspection` and its Lens types from the deleted `@epicenter/lens/legacy` (ADR-0227). Rebuilding it is not a reimport. ADR-0226 withdrew what it read: it opened a replica the host owned, and an application on the store writes to its own client-owned store instead, so a reader that wants an application's rows becomes a replica of the authority that application uses.
- Home renders one row and calls one native verb (`launch_application`), which dispatches privately to a compiled surface window or an `app-` window and settles on that window's real outcome rather than on having scheduled it. Rust validates the ID's shape only: catalog membership is Bun's alone (ADR-0179), and an ID naming no member resolves to a window Bun answers 404. Never re-derive the catalog in Rust, do not add a second launch command, and do not reuse ADR-0181's app-facing `openApp(appId)` name for it.
- A compiled application is exactly a `dist/<id>` build `COMPILED_APPLICATIONS` declares. `loadStaticAssets` loads every one and the server serves each below `/apps/<id>/` through the shared contained resolver, so adding one is a list entry plus a build script, never another asset field, resolver, or route handler. A declared application that did not build refuses the boot (ADR-0190). An admitted catalog member is served by that same loop and is not a lesser kind of page: its document is held in memory, gated behind a browser session, stamped with the auth bootstrap, and hashed into the one CSP, exactly like a compiled one. Serving an app's document straight off disk skips all four, and the app boots blank because the browser refuses its own start script.
- There is no host-owned replica, and a build cannot reach one. Every build opens its own store and reaches one authority per signed-in account (ADR-0226, widened to every surface by ADR-0227). The `epicenter-host` resolve condition survives for exactly one thing: the host really does broker a credential its windows cannot obtain, so `#platform/auth` and `#platform/instance` select the desktop bootstrap under it. Never detect the host at runtime, never widen `tauri` to mean it, and never reintroduce a storage seam behind it.
- An application window gets a capability file only when it calls a native command. Same-origin HTTP to the Bun host needs no grant; the trusted-app capability is Whispering's own authority, not a compiled application's default (ADR-0190).
- `src/main.ts` resolves the one Epicenter data root by calling `epicenterDataRoot()` from `@epicenter/constants/app-data`, and derives `data/`, `blobs/`, and `app-catalog/` below it. Rust does not pass a root in, and no other TypeScript may compute one: a host and a CLI that disagree here write to two different mailboxes (ADR-0201). The one native resolution left, `src-tauri/src/app_data.rs`, exists because the staged-recording blob store runs before the host could have told it anything, and it is pinned equal to the TypeScript one by a test.
- Every trusted app owns one directory under that root, `apps/<app-id>`, named by the id it is admitted or composed under (ADR-0201). Allocation is nominal: the host issues the id and creates nothing, and it reclaims nothing when an app leaves. There is no reserved-id list and adding one would be a regression: an admitted app's id is the namespace it declares, which always contains a dot, and every id this host issues itself is a bare label, so the two sets cannot collide by grammar (ADR-0210). Do not give a webview a path into any of it: reach is undecided, and the handle has no filesystem in it (ADR-0181).
- `src/folder/` renders every Lens table to markdown under `~/Epicenter` and reads edits back, and `src/folder-catalog.ts` puts its two verbs on the host's action surface as `folder__status` and `folder__push` (ADR-0207). The folder is not optional and takes no flag: `createHomeHost` requires it, `push` is a `mutation` so the session's approval gate is the review step, and neither verb accepts an argument because any narrowing flag could skip the deletion section of a push. Do not add a watcher, a conflict prompt, or a second write path; `push` is the only door and it sends only the fields that differ from the receipt of what was last rendered.
- `src/folder/project.ts` writes the queryable half of the same folder: one read-only `~/Epicenter/<namespace>/<app>.sqlite3` per Lens, one real table per Lens table (ADR-0208). It does not build today: it imports `lensTableExtractionSql` from `@epicenter/data/legacy/inspection`, and the superseded stack is deleted (ADR-0227), so that subpath is gone. `@epicenter/data` has exactly four entry points: `.`, `./bun`, `./browser`, and `./sync`. Whatever replaces the import, the SQL stays imported and never restated, because ADR-0162 owns what a Lens table looks like as a relation and two spellings would drift. The file is rebuilt from empty at every boot rather than migrated, which is what makes read-only true without a filesystem mode, and the replica is attached `mode=ro` so a write against it fails in the engine. Never make a projection writable, never let SQL become a write path, and never put a second database in one app folder.
- `src/workspace-owner.ts` owns the one Device runtime and the closed built-in definition catalog. Home services receive typed handles from that owner; trusted SPAs use the same-origin workspace API. Neither receives a SQLite path.
- `src/host.ts` composes canonical in-process app catalogs, optional boxed stdio MCP tools, and optional read-only local sources into one namespaced `ToolCatalog`. The host does not open root-Yjs persistence or own a second data directory.
- `src/workspace.ts` defines the Device-owned `epicenter-conversations` workspace. Boot resumes the latest durable row or creates one `New Chat` row before opening its document. `clear` creates another row. Home releases and flushes row documents before the workspace owner disposes.
- Local sources remain host-owned and are never remote routes or capabilities. Finished history belongs to the durable workspace plane.
- Command semantics belong to the host session, not the WebSocket adapter. Chat sends, direct invocations, approval answers, and later palette or voice commands must route through one host-owned session command surface.

## Refusals (do not reopen without a new ADR)

- No daemon `mount.ts` as the composition model; the mount path is CLI/projection for one app.
- No MCP for first-party in-process apps; MCP stays the boxed-app airlock (ADR-0081).
- No loose in-process TypeScript tool modules in v1; future scripting starts from an out-of-process runner unless a new ADR explicitly accepts unsafe developer-mode host imports.
- No bundled Tauri SPA plus side IPC; Bun serves the SPA and the API from one loopback origin.
- Epicenter admits inert built app folders and never installs dependencies, runs an app's build system, or reads application source. A folder from a publisher URL, a self-hosted builder, a local developer build, or offline media enters through the same boundary with the same authority (ADR-0179).
- No registry, publisher identity, artifact signing, or update mechanism. ADR-0179 decides admission only; anything downstream of it needs its own ADR.
- No per-app permission, capability grant, or device prompt. An app window runs as Epicenter: shared origin and session, OS-granted browser device access, and the one app-window native surface. Do not describe the capability file as a sandbox (ADR-0179).
- Applications never choose the local transcription model. Home owns the one active model and its administration; apps request transcription and may still choose their transcription route (ADR-0180).
- No fifth Home pane, no global rail, and no installation, update, or removal UI. Home has Apps, Data, Chat, and Settings; Data is Epicenter's own job (ADR-0209) and the namespace list inside it is that pane's mode selector, not a rail. A rail still needs a launchable list large enough to earn it, and app management still needs real operations before it needs a screen (ADR-0189).
- The loopback server always binds `127.0.0.1` and rejects every request without the per-launch token; this ships with the first server version, not later (ADR-0084).
- No HTTP command route, Tauri IPC command path, stdio command protocol for the browser UI, generic synced command table, or transport-adapter framework until a real second consumer earns it. The current WebSocket is a session adapter, not the architecture.
