# The switch: the store opens document handles, and the transport goes

**Status**: In Progress
**Date**: 2026-08-28, rewritten 2026-08-29 against ADR-0280 through ADR-0287

## What this is

The one commit ADR-0277 needs, and everything around it is now built and green.
This document is written to be picked up cold: the decisions are in ADR-0276
through ADR-0287, and what follows is the order of operations, the oracle, and
the hazards that have already bitten.

in the store yet:

**Four silent bugs have been found in this code, all by adversarial review
rather than by tests failing.** None threw, none rejected, and every one left
`durability.healthy` reading green. Read `06215bb5` and then `e1de7c6d` before
writing anything that touches the record.

All four were one remembered sequence disagreeing with disk. `06215bb5` made
the class loud (`add`, never `put`); `e1de7c6d` removed the number, so a write
reads the top of its chain inside the transaction that extends it, the way the
authority twin always has. The invariant to keep is now stateable: **no memory
state names a key or bounds a delete.** What is left in memory is advisory and
can make a fold wasteful or late, never wrong. `add` stays anyway, because it
is what makes "unreachable" audible.

The remaining silent class is the one a constraint cannot reach: a DELETE with
a wrong argument. `retire`, the fold's bound, and `appendAndRetire`'s second
argument all take a bare string and succeed on a wrong one, because a delete
has no key to collide on. Only ownership closes that, which is the case for
`claim(doc)` eventually returning a per-document chain rather than a release
function. Not in this switch; noted so it is not rediscovered.

## Why it cannot be split

Every candidate intermediate fails at the same joint. `DurablePort`'s `load()`
returns `{ updates, outbox: OutboxEntry[], cursor, lastId }`: a chain of
appends, a queue of unsent ones addressed by id, and a log position. **That
contract is the log.** The new record keeps the chain and drops the other
three, so there is no adapter that satisfies both contracts without carrying
the queue and the cursor it exists to delete.

**And it cannot be split the other way either**, which was tried on paper and
is worth writing down so nobody tries again. "Swap the storage first, delete
the transport second" fails because the transport writes THROUGH the
persistence controller: `SyncEngine.applyRemote`, `ClientLog.acknowledge`,
`adoptDocumentIdentity`, and `DataStoreBase.persistence` all reach it. Deleting
the controller deletes the transport; keeping it means two writers to one
document, the controller and the handle's own eager append.

So this is one commit that goes red in the middle, followed by one commit that
is pure deletion. Budget for the red.

So the port does not move to a new medium. It stops existing.

## The oracle

The claim the whole plan rests on: **the typed surface does not move.**

- **77 tests never mention a port, cursor, outbox or envelope, and survive
  unchanged**: invariants 18, document-authority 15, deletion-model 9,
  document 7, delta-names-the-row 7, validation 7, document-frames 6,
  what-the-crdt-buys 5, authority 2, independent-document-roots 1.
- **`store.test.ts` has 61 tests and 6 transport references**, all in its setup
  (`createSqliteDurablePort` to build a store, `encodeEnvelope` to deliver
  remote bytes) plus one test about the outbox.

**≈137 tests must come back green with only `store.test.ts`'s setup changed.**
If they do, the surface did not move; if one fails on anything but setup, stop
and read it rather than adjusting it.

Two suites leave the oracle rather than passing it: `blobs.test.ts` (15) and
`flush-on-hide.test.ts` (7) test files this commit deletes. `document-handle`
(8) and `document-sync` (13) are rewritten with the handle, so they are the
work rather than the check on it.

## Order of operations

Each step compiles. Only the last is expected to go red, and only in the files
being deleted.

1. ~~`record.ts`: the durable record~~ **landed in `d043cd1a`**, with the
   review's two corrections in the commit after it. The shipped surface is
   `read` / `append` / `shouldFold` / `fold(doc, encode)` / `retire` /
   `durability` / `close`, and `encode` is a callback precisely so no caller
   can hand this file a promise to await inside a transaction.
2. ~~`fold.ts`: one rule, imported by both sides~~ **landed in `ba5176f8`**.
3. **The openers take a generation and open a root handle over the record.**
   `openLocal(definition, { generation })` and
   `openAccount(definition, { baseURL, principalId, generation })`. The caller
   resolves the number before opening: it is a path segment in the URL, and
   boot redirects when it is absent (ADR-0285). `createLocalStore` and
   `createAccountStore` stop taking a `DurablePort` and become asynchronous,
   because opening a handle is a hydration. The root document's key is `app`;
   a row document's key is `<table>/<rowId>`. The generation is the database
   name, not a key segment. There is no local ledger to read and no selection
   to store; the offline list is `indexedDB.databases()` filtered by prefix,
   and a generation is complete when its `app` document is present.
4. **`documents.ts` becomes the handle map.** `open(address)` returns a handle
   from the map or opens one; `close` removes it. Delete `acceptRemote`,
   `retire`'s durable half, and `states()`: a handle persists itself and there
   is no batch to join. The handle owns the doc, the record, the idle timer,
   and an optional session. ~~Absorb `document-session.ts`~~ **already done in
   `72cc325a`**, against `sync/document-session.ts`, which no longer exists.
   There is nothing left to absorb; a literal reading of the old sentence sends
   you hunting for a file that is not there.

   **`RowDocumentHandle` does not move.** It is `{ get(root, typeName?),
   [Symbol.dispose]() }` (`documents.ts:72-75`) and honeycrisp consumes exactly
   those two members (`app.svelte.ts:265,271-272`). `DocumentHandle` is a
   richer nine-member shape, so the map ADAPTS DOWN to `RowDocumentHandle`
   rather than widening what a table hands out. This is oracle surface: if it
   moves, the oracle is not measuring what it claims to.

   **The refcount stays here.** `record.claim` is a tripwire, not a dedup: a
   second claim on one address THROWS (`record.ts:614`), and the record's own
   comment says a manager "should still hand out one handle per address"
   (`record.ts:239-244`). So the map keeps `address -> { handle, references }`,
   opens on the first `open()`, closes at zero, and increments before the
   hydrating await resolves, the way `documents.ts:291` already does.
5. **Row deletion retires without a tombstone table.** `deleteRow` removes the
   scalar row and the document's chain by key range. `_tombstones` and
   `DocumentRetired` go: what they prevented, a derive re-minting a deleted
   row, is unreachable since `updateRow` cannot mint (074d1deb).
   **The record is one verb short and gains it here.** Removing the scalar row
   is an append to the `app` chain and retiring is a separate transaction on a
   different key range. One database makes a combined verb possible, so
   `record.ts` grows one rather than keeping an ordering rule that leaves
   debris on a crash.

   It also grows enumeration, `documents()`, which nothing needed until the
   export path did (ADR-0286 makes every mint read one) and which a namespace
   with no listing API cannot fake.

   **Two things go with `_tombstones` that this step does not name, and one is
   a behaviour change.** `states()`'s only caller is `encodeSnapshot`
   (`store.ts:1913-1926`), which needs `record.documents()` plus per-document
   bytes instead; that is a compile error rather than a silent one, but it is
   not optional and it lands here. And `DocumentRetired` had a SECOND job
   beyond the resurrection `074d1deb` made unreachable: it refused to open a
   retired address at all (`documents.ts:268`, re-checked post-hydration at
   `:297` for the mid-hydrate race). Deleting it drops that refusal. Decide
   deliberately whether the combined delete verb closes the race by ordering,
   or whether this is an unstated regression.

   **Nothing here says who closes a LIVE handle when its row is deleted.** A
   component holding a `RowDocumentHandle` on a just-deleted row would keep
   writing into a `Y.Doc` whose chain is being deleted underneath it. The map
   from step 4 has to evict, and that is not the same thing as `retire`'s
   durable half.
6. **`store.ts` loses its transport half.** `ClientLog`, `SyncEngine`,
   `syncEngineOf`, `SyncCapability`, `SyncFacts`, `createClientLog`,
   `coalesce`, `acknowledge`, `cursor`, `documentIdentity`,
   `adoptDocumentIdentity`, the `Unstampable` error, and
   `stateVector`/`encodeStateSince` (which move to the handle and are per
   document, not per store). `persistence` shrinks to
   `durability: { healthy, subscribe }`, which is the one thing eager appends
   must not silently lose.
7. **`browser.ts` and `memory.ts` open records.** browser opens the idb
   record and already asks for persistent storage (`b47598dc`). `memory.ts`
   opens `openMemoryRecord`, loses its `bun:sqlite` dependency, and **moves to
   the test tier** beside `test-locks` and `test-opfs`: it has 85 call sites
   and not one of them is outside a `.test.ts`, so it is test infrastructure
   sitting in the barrel beside the two real openers. Its optional
   `MemoryRecord` parameter collapses to a name, because a memory chain
   outlives its record and is keyed by one. When this lands, `packages/data`
   stops linking SQLite on the client, which ADR-0280 claims and cannot yet
   say.
8. **`attach.ts` dials per document.** One socket per open handle, at
   `/api/data/v1/<dataId>/generations/<n>[/<table>/<row>]` (ADR-0283). The
   classify-with-a-`GET` path loses the reason it was written: nothing is ever
   `410` now (ADR-0287). Check before deleting it, because a client may still
   want to tell a refused credential from a transient failure, and only the
   deleted-generation arm is gone.
9. **Delete.** `persistence.ts`, `log.ts`, `client.ts`, `connection.ts`,
   `hub.ts`, `authority.ts`, `frames.ts`, `envelope.ts`, `blobs.ts`,
   `blobs.opfs.ts`, `test-opfs.ts`, `flush-on-hide.ts`, `document-session.ts`,
   plus `port-conformance.test.ts`, `transport.test.ts`, `connection.test.ts`,
   `persistence.test.ts`, `sync.test.ts`, `attach.test.ts`,
   `document-identity.test.ts`, `retention.test.ts`, `blobs.test.ts`,
   `flush-on-hide.test.ts`, and `evidence/browser/two-records.ts` (it guards an
   OPFS pool failure that cannot occur under idb). Move `CHUNK_BYTES` and
   `intoChunks` into the server authority before `frames.ts` goes, or the build
   breaks. Drop the `document-` prefix from the remaining sync files, because
   the old names are free.

## Two open items that no record carries

Both were found by a session working this same branch whose findings never
reached the repository. They are written here rather than left in a transcript,
which is the whole reason this section exists.

### The origin door, and what replaces it

`store.ts:1292-1300` throws when an `updateV2` arrives under an unrecognised
origin. That is the door: it stops a stranger's direct `Y.applyUpdateV2` from
being persisted and republished as this device's authored work.

The new handle applies remote frames with **no origin**, and
`document-handle.ts` says so deliberately, because `deriveOnCommit` tells a
local commit from a remote one by `transaction.local`. But a stranger's direct
apply looks *exactly* the same: no origin, `local === false`. So after the
switch the door is gone, and `store.test.ts:919` ("a direct `Y.applyUpdateV2`
on a live row document throws instead of forging authored work") goes red even
though it names no transport and the oracle counts it as a survivor.

Half the old rationale expired: under state-vector sync nothing is "authored"
and everything a document holds is offered. **The other half got worse.**
Foreign bytes whose causal dependencies are missing are buffered by Yjs, never
appended, never in a state vector, and held by no authority. Silently gone,
which is the failure mode this design keeps producing.

**Proposed, and not yet taken:** `receive()` applies with a private origin
sentinel, and `deriveOnCommit` discriminates on that sentinel rather than on
`transaction.local`. Both jobs survive: derive still tells local from remote,
and a stranger is still distinguishable from a frame, so `:919` keeps its body.

It contradicts a comment written into `document-handle.ts` on 2026-08-29
warning that "a later refactor that passes an origin here breaks the
discrimination silently". That warning is correct only while the discriminator
IS `transaction.local`. Moving the discriminator to the sentinel preserves it.
**Decide before the commit; do not discover it in the red.**

### The zombie socket, which is a protocol gap rather than a bug

The old protocol noticed a dead-but-open socket two ways: an acknowledgement
watchdog and a gap-triggered reconnect. The new protocol has neither, because
it has no acknowledgements and no positions.

`document-handle.ts` advances `peerVector` the moment bytes reach the wire, and
says why: if the socket dies in flight, the peer's next step 1 says otherwise
and the update is sent again, which is free. That reasoning is sound **and
nothing causes the reconnect.** `hub.receive` returning `false` tells the HOST
to close; nothing tells the CLIENT its socket is a zombie. A device can sit
indefinitely believing it is synced.

This needs an owner before `connection.test.ts` is deleted, because that suite
is where the old detection lives. The candidates are a ping/pong or a periodic
re-announce, and a re-announce is nearly free: step 1 is a state vector, an
authority that has nothing new answers with a 13-byte no-op, and re-announcing
is already what a reconnect does. **This is a design decision, not an
implementation detail, and it is not made.**

## Hazards, in the order they will bite

- **`store.test.ts`'s `exchange()` rides on `encodeEnvelope` + `applyRemote`,**
  and about ten of the package's most valuable tests ride on it:
  delete-beats-edit, kv both-survive, corrupt-peer conformance. They must be
  rewired onto two handles through a hub IN THIS COMMIT, or they get deleted by
  accident along with their transport.
- **About 4,900 lines of test die with their subjects**, and should die in the
  same commits rather than before: `persistence.test.ts`,
  `port-conformance.test.ts`, `sync.test.ts`, `connection.test.ts`,
  `transport.test.ts`, `document-identity.test.ts`, `attach.test.ts`,
  `authority.test.ts`, `blobs.test.ts`, `flush-on-hide.test.ts`. Before
  deleting `attach.test.ts`, note what only it covers: denial classification,
  where calling a refusal transient spins a backoff forever, silently. That
  coverage has to be rebuilt when the new dial exists.

- **A sync bug does not throw.** It under-sends, and the other device is
  quietly missing a paragraph. The ordering rule is the guard: bytes durable
  before anything says they were sent. Under eager appends this gets easier,
  because durability now precedes the idle timer instead of racing it.
- ~~**`document-handle.ts:66-72` argues the opposite of the settled model.**~~
  **Already fixed.** The file now says the opposite at `:24-31` ("An earlier
  version of this file said the durable write and the push are the same
  moment... and saying so cost a person's unsaved work"). Nothing to do.
- **`store.test.ts:952`** (was `:935`; the file has shifted, so re-verify every
  line number in this document before trusting it) asserts "local commits leave
  the outbox empty and no replica verb exists". It tests a mechanism rather than a behaviour, and what
  it protected, a device store must never grow work it owes nobody, is
  unreachable when there is no outbox. **Delete it rather than translate it.**
- **`deriveOnCommit` fires on a row document's commit.** Under handles it must
  still reach the root handle's document, which is a different handle. This is
  the one cross-handle call in the design and the place to look first if a
  derived title stops updating.
- **`claims.ts` locks a store address.** The lock moves to the ledger name,
  without `gen/<n>`, because a device draining one generation while reading
  another holds two databases open. A handle does not take its own lock: two
  handles on one document are the same handle, from the map.

## After it lands

Wave B: the mirror takes the record and a table subscription rather than the
database's private surface, and `stored()`/`onCommitted()` leave
`DataStoreBase`.

Wave C: `view` and `store` stop being two objects, because the measurement that
justified them ("thirteen names where four are used") expires with the
transport. `LocalStore | AccountStore` collapses to one `Store` type at the same
time, since the `sync` discriminant now discriminates a capability that is not
store state; the two openers stay two openers, because the realm is an address
fact. Then `store` becomes `database`, once, over a surface that has stopped
moving.

Not in this commit, and each tracked by its own record: the index/record field
split (ADR-0284), which changes the definition layer and the typed surface and
must not ride an oracle whose entire claim is that the typed surface did not
move; the URL-carried generation (ADR-0285), which is a routing change in the
application rather than a store change; and the server's ledger (ADR-0283 as
amended by ADR-0287), which is a different package and needs no client change
to land.

Delete this spec when the switch lands. The decisions are already ADRs; this is
scaffolding.
